Nuclei is the open-source quantum workspace — learn it, research it, run it on
real hardware, all local and private. For
developers it is four things: a scriptable simulation kernel behind a plain
[WebSocket JSON protocol](/docs/kernel-api/overview/), a multi-framework
abstraction that normalizes Qiskit, Cirq, CUDA-Q, and Q# into one
[`CircuitSnapshot`](/docs/kernel-api/schemas/) format, a gateway that submits
the same circuits to real quantum hardware, and an AI layer
([Dirac](/docs/dirac/architecture/)) that calls `api.anthropic.com` directly
with a user-supplied key — no Nuclei server in the loop. If you want to *use* Nuclei,
[download the app](https://getnuclei.dev/#download) or
[try it in the browser](https://getnuclei.dev/try/) — this site is for people
**building on** Nuclei.

Google Quantum AI is **scaffolded only**: a provider stub exists in the
kernel but always refuses to connect, and its Launch-portal tile is disabled
("Research access only"). Don't build against it yet.

## Find your path

- **Inspect** — see exactly what the compiler does to your circuit, pass by
  pass, with the [Transpiler Explorer](/docs/developer-tools/transpiler-explorer/).
- **Integrate** — drive the kernel from your own client, grader, or notebook:
  [Kernel API overview](/docs/kernel-api/overview/).
- **Extend** — add a framework adapter, hardware provider, or contribute to
  the IDE: [framework adapters](/docs/extending/framework-adapters/),
  [hardware providers](/docs/extending/hardware-providers/),
  [contributing](/docs/extending/contributing/).
- **Evaluate** — understand how the pieces fit before committing:
  [architecture](/docs/introduction/architecture/) and
  [desktop vs web](/docs/introduction/desktop-vs-web/).

<Aside type="note" title="Protocol v1">
These docs describe **kernel protocol v1** as of Nuclei 0.5.x. Additive
changes land without notice; breaking changes ship only with a protocol
version bump and an entry in the
[protocol changelog](/docs/reference/protocol-changelog/).
</Aside>
