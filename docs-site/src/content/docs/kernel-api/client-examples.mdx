Two complete clients that connect, parse a Bell circuit, execute it, and
print the measurement histogram. Both implement the one pattern every
kernel client needs: **drain messages until the terminal type arrives**,
relaying any interleaved `output`/`stderr`/`error` along the way (see
[the streaming model](/docs/kernel-api/overview/#the-streaming-model)).

Start a kernel first:

```bash
cd kernel && python server.py
# Nuclei kernel ready on ws://localhost:9742
```

## One-off requests from the shell

For poking at the protocol without writing code,
[websocat](https://github.com/vi/websocat) works well with the fixture files
from `docs-site/fixtures/` — every documented request is sitting there as
ready-to-send JSON:

```bash
# jq -c compacts the pretty-printed fixture to one line (websocat sends one
# frame per input line); --no-close keeps the connection open after stdin
# EOF so the response frames have time to arrive.
jq -c . docs-site/fixtures/run_python_hello.request.json | websocat --no-close ws://localhost:9742
```

Each response frame prints on its own line; exit with Ctrl-C.
